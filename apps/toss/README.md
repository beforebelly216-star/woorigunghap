# 우리사주 앱인토스 WebView

- 앱 이름: `woorisajoo`, 표시명: `우리사주`
- SDK: `@apps-in-toss/web-framework` 3.7.0, React 18, TDS 2.5.1
- 용도: 콘솔 업로드/화면 확인용 테스트 번들. 정식 출시용이 아니다.
- 화면: 홈, 무료 서비스 입력 미리보기, 보관함, 내 계정, 이용 안내.
- 최신 결정: 미니앱 유료 결제를 제거하고 광고만으로 수익화한다. IAP 준비 코드는 미사용이며 콘솔 SKU 등록을 중단한다. 기존 웹 구매를 보존한다.
- SDK 로그인·메모리 세션·보관함 조회·로그아웃 코드를 추가했다. 현재 공개 API/인증서 설정이 없어 로그인은 비활성화다. 서버 계산·인앱결제·광고·초대/공유·결과 저장은 미연결이다. 입력 화면은 미리보기이며 전송/영구 저장하지 않는다.

## 서버 연결 준비

`.env.example`의 `VITE_API_BASE_URL`에는 승인된 공개 API Origin만 설정한다. 서버 인증서·비밀키를 넣지 않는다. root `.env.example`의 토스 서버 설정 및 인증된 연결 해제 콜백을 준비한 뒤 토스앱 실기기로 검증한다. 토큰은 메모리 전용이며 앱 재시작 시 다시 로그인한다.

`node scripts/session-iap-test.mjs`로 세션/동시 요청/미결 주문 처리 어댑터를 검증한다. IAP 어댑터는 아직 구매 UI에 연결하지 않았다. 서버 영구 지급·주문/입력 연결·결과 복구·환불 처리가 완료되기 전에 구매 버튼을 활성화하지 않는다.

## 빌드

이 디렉터리에서 `npm ci`, `npm run build`를 실행한다. 공식 `ait build`가 `woorisajoo.ait`를 생성한다. `node scripts/check-bundle.mjs`로 앱 이름, 포함 파일, 권한, 크기, SHA256을 확인한다. 개발 서버는 `npm run dev`로 연다.

기존 Next.js 서버와 의존성을 분리했다. 서버 비밀 환경변수를 이 프로젝트에 복사하지 않는다. `.ait`와 `dist`는 Git에 넣지 않으며 필요할 때 다시 생성한다.

## 광고 준비

운영 광고 그룹 ID는 `src/ad-config.js`에 등록했다. 배너 1개와 사용자 확인된 전면형 2개이며, 1차를 기본 전면형에 연결하고 2차는 후속 배치용으로 보관한다. 보상형은 미제공이다. 환경변수로 유형별 값을 재정의할 수 있다. `node scripts/ad-config-test.mjs`는 운영/테스트 ID 분리와 전면형을 보상형으로 사용하지 않는 경계를 확인한다. 개발 번들은 광고 OFF를 유지하며 ID 등록만으로 광고를 활성화하지 않는다.

홈/실제 보관함에는 단일 배너 슬롯이 있다. 공식 배너·전면/보상형 SDK 어댑터와 배너/전면 ID는 준비했으나 실제 결과/서버 권한·저장 연결 전이므로 기본 OFF다. 테스트는 `node scripts/ad-test.mjs`. 공개 광고 그룹 ID만 `.env.example`의 유형별 항목에 설정하고 테스트에서는 운영 ID를 쓰지 않는다. 결과·추가 상세 해설·분석 후 전환에는 후속 단계에서 연결한다. 빈도/정책/남은 작업은 `../../docs/TOSS_AD_MONETIZATION.md` 참조.

## 콘솔 업로드

콘솔의 해당 앱 → 앱 출시 → 새 버전 등록에서 `woorisajoo.ait`를 업로드하고 QR 테스트한다. CLI build가 출력하는 deploymentId는 번들 식별자이며 실제 콘솔 업로드/배포 완료 증거가 아니다.

이 파일로 출시 검수를 요청하지 않는다. 미완료 기능 안내와 비활성화 버튼이 있으므로 공개 출시 요건을 충족하지 않는다. 로그인 인증서·서버 인증/연결 해제·탈퇴·무료 결과·광고형 상세 생성 권한/저장 복구·정책·실기기 QA를 마친 뒤 새 번들을 생성한다. 자세한 계획은 `../../docs/APPS_IN_TOSS_MIGRATION.md`를 따른다.
