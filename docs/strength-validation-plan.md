# 우리궁합 신강약 엔진 검증 게이트 v1

기준일: 2026-08-12
상태: Day 6 검증 기준 / production 승격 전 필수

## 1. 핵심 정정

10개 표본의 분포가 `WEAK 4 / BALANCED 4 / STRONG 2`로 보였다는 사실만으로 shadow v2가 타당하거나 정상이라고 판단하지 않는다.

10개 표본은 다음만 확인하는 **sanity check(기초 동작 확인)** 이다.

- 계산이 결정론적으로 반복되는가
- 점수가 한쪽 극단으로 폭주하지 않는가
- 누락/NaN/경계 오류가 없는가
- 코드 변경 후 회귀가 없는가

**분포가 고르게 보이는 것 자체는 정확성 근거가 아니다.** 목표 분포에 맞추기 위해 가중치를 조정하지 않는다.

## 2. production 검증을 두 층으로 분리

### A. 구조 커버리지 / 스트레스 테스트

목적: 알고리즘의 안정성, 경계, 불연속, 편향을 찾는다. 정답률을 주장하는 테스트가 아니다.

최소 커버리지:

- 10개 일간 × 12개 월지 = 120개 기본 층 전부 포함
- 각 층에서 통근 강/중/약 케이스 포함
- 비겁·인성 우세 / 식상·재성·관살 우세 / 혼합 구조 포함
- 시주 있음/없음 포함
- 입춘·절입 경계 포함
- 합·충·형·파·해 및 삼합·방합·육합 후보 포함
- 극단 편중 및 종격 후보 구조 포함

권장 규모: 최소 360개, 가능하면 600~1,000개 자동 생성/샘플링.

검사 항목:

- 동일 입력 반복 동일성 100%
- 입력 A/B 또는 시간 시나리오 순서에 따른 비의도적 결과 변화 0건
- 경계 1분/1일 차이에서 설명되지 않는 대폭 점프 탐지
- 특정 일간/월지에만 기계적으로 신강/신약이 몰리는지 탐지
- 시간 미상 시나리오 중앙값/범위 안정성

주의: 이 단계의 클래스 비율은 '정답 분포'로 사용하지 않는다.

## 3. 독립 기준셋 검증

목적: 실제 판정 타당성 검증.

코드와 같은 산식으로 만든 라벨을 정답으로 쓰지 않는다. 그러면 순환검증이 된다.

기준셋은 코드 밖에서 판정된 명식을 사용한다.

권장 최소:

- 50개: 임시 검증 가능
- 100개 이상: production 승격 권장
- 10일간과 12월령이 최대한 고르게 포함되도록 층화
- 신강/중화/신약, 경계형, 종격 후보를 모두 포함

각 사례에 보존할 정보:

- 원국
- 得令(득령) 판단 근거
- 得地(득지)/通根(통근) 판단 근거
- 得勢(득세) 판단 근거
- 합화/회국 반영 여부
- 수동 판정: 신강 / 중화 / 신약 또는 갈림
- 판정 출처/근거

## 4. 평가 지표

단순 정확도 하나만 쓰지 않는다.

- 3분류 정확도
- 인접 허용 정확도: 신약↔중화, 중화↔신강 1단계 차이와 신약↔신강 직접 반전을 구분
- 극단 반전율: 수동 신강을 자동 신약으로, 또는 그 반대로 판정한 비율
- 경계 사례의 confidence 적절성
- 일간별/월지별 오류율

production 승격의 핵심 목표는 '모든 사례를 맞힌다'가 아니라 **큰 방향을 뒤집는 오류를 매우 낮추고, 애매한 사례는 confidence를 낮춰 확정하지 않는 것**이다.

## 5. shadow v2의 현재 지위

`strength-shadow-v2`는 후보 알고리즘일 뿐이다.

- 35/30/35 가중치는 아직 승인된 절대 기준이 아니다.
- 현재 10개 표본 결과는 calibration/기초 동작 확인용이다.
- 구조 커버리지와 독립 기준셋 검증이 끝나기 전에는 `productionScoringEnabled=false`를 유지한다.
- 합화·삼합·방합 보정을 추가하기 전 현재 점수로 용신을 확정하지 않는다.

## 6. 다음 순서

1. 구조 커버리지 생성기 작성(최소 120층, 권장 360+ 사례)
2. 합화·삼합·방합 실질 세력 보정 구현
3. 독립 수동 기준셋 50~100개 확보/정리
4. shadow v2와 기준셋 비교
5. 오류 사례를 유형별로 분석
6. 가중치/임계치 수정은 오류 근거가 있을 때만 수행
7. 별도 holdout 사례로 재검증
8. 사용자 최종 승인 후 production 승격

## 7. API 비용 원칙

위 모든 검증과 production 점수 계산은 규칙 기반 서버 연산으로 수행하며 LLM/API 호출은 필요하지 않는다. AI는 확정된 계산 결과의 자연어 서술에만 선택적으로 사용한다.
