# 우리궁합 만세력 계산 정책 v1

## 목적
우리궁합의 사주 원국은 AI가 계산하지 않는다. 동일 입력은 동일 계산 버전에서 항상 같은 결과를 반환해야 하며, 계산 정책이 바뀌면 버전을 올려 기존 구매 결과와 분리한다.

## MVP 고정 정책
- 엔진: `manseryeok` 2.0.0
- 정책 버전: `manse-policy-v1`
- 시간대: 한국 표준시 KST (`Asia/Seoul`, UTC+09:00)
- 연주: 입춘 순간 기준
- 월주: 절기(節) 경계 기준
- 일주 경계: 자정(`midnight`)
- 23:00~23:59 출생을 다음 날 일주로 넘기지 않는다.
- 진태양시/출생지 경도 보정: MVP에서는 적용하지 않는다.
- 계산은 서버에서만 수행한다.

## 출생시간을 모르는 경우
출생시간을 임의값으로 확정하지 않는다.

1. 같은 입력 날짜의 00:00과 23:59를 각각 계산한다.
2. 일주는 자정 경계 정책상 같은 날짜에서 동일해야 한다. 다르면 계산 엔진/정책 오류로 처리한다.
3. 입춘 또는 절입 시각이 그 날짜 안에 있어 연주/월주가 달라질 수 있으면 해당 기둥을 확정하지 않고 `null` 및 경계 경고를 남긴다.
4. 시주는 항상 `null`로 저장한다.

## 양력/음력
- 양력 입력은 그대로 계산한다.
- 음력 입력은 `manseryeok`의 KASI 기반 한국 음력 테이블을 통해 양력으로 변환한다.
- 음력 입력에서는 윤달 여부를 함께 전달한다.
- 계산 스냅샷에는 원 입력 달력/날짜와 변환된 양력 날짜를 모두 기록한다.

## KASI 검증 범위
한국천문연구원(KASI) 공공 OpenAPI는 운영 시 매 계산마다 의존하는 런타임 엔진이 아니라 Day 5 및 회귀 테스트용 검증 oracle로 사용한다.

공식 대조 대상으로 사용:
- 양력 ↔ 음력 변환
- 윤달 여부
- 일진(`lunIljin`)

직접 정답으로 사용하지 않는 항목:
- `lunSecha`
- `lunWolgeon`

위 두 값은 입춘 순간·절기 경계를 사용하는 사주 연주/월주와 경계에서 정의가 달라질 수 있으므로, 연주와 월주는 별도의 절기 경계 골든 테스트로 검증한다.

## Day 5 검증 전략 — 30개 골든 테스트
최소 다음 그룹을 포함한다.

- 일반 양력 출생
- 일반 음력 출생
- 윤달
- 입춘 직전/직후
- 주요 절입 직전/직후
- 00:00 전후
- 23:00 전후
- 윤년 2월 29일
- 월말/연말
- 출생시간 미상
- KASI 음양력 변환 대조
- KASI 일진 대조
- 국내 만세력 앱 2~3개 보조 대조

## 불일치 처리 원칙
1. 외부 앱과 다른 결과가 나왔다고 즉시 우리 값을 수정하지 않는다.
2. 먼저 시간대, 자시/야자시, 진태양시, 입춘/절입 기준 차이를 확인한다.
3. KASI/절기 데이터와 우리 고정 정책을 기준으로 원인을 기록한다.
4. 계산 정책 자체를 변경해야 한다면 `MANSE_POLICY_VERSION`을 올리고 기존 구매 결과를 재계산하지 않는다.

## 저장해야 할 버전 정보
모든 계산 스냅샷은 최소 다음 값을 포함한다.
- `engineVersion`
- `policyVersion`
- `timezone`
- `dayBoundary`
- `trueSolarTimeApplied`
- 원 입력 달력/날짜
- 변환 양력 날짜
- 경계 불확실성 정보
