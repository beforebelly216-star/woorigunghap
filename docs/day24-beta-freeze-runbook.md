# Day 24 베타 동결·출시 준비 런북

기준 브랜치: `main`
Day 24 상태: **완료**

## 완료 판정

2026-08-18 기준으로 24일 MVP 개발 계획을 완료한다. Day 24부터는 새 기능 완성도를 더 끌어올리기 위해 출시를 지연하지 않고, 실제 사용 중 발견되는 문제를 운영 백로그로 보완한다.

완료 판정의 필수 기준은 다음과 같다.

- 1:1·1:N 핵심 상품 흐름 구현 완료
- 서버 만세력·궁합 계산, 결제 입력 바인딩, 저장·복구, 계정 권한, 웹훅 멱등, AI single-flight 구현 완료
- 개인정보 비식별화 및 서버 전용 비밀값 경계 유지
- 1:1 CH0~CH9 상세 리포트 및 5개 관계 유형 편집 구조 구현 완료
- 1:1 목표 분량 약 5,000~8,000자, 필요 시 최대 약 10,000자 정책 반영
- 문장 취향성 문제는 `qualityWarnings`로 기록하되 출시 blocker로 사용하지 않는 progress-first 정책 반영
- 최신 기능 기준 Core calculation validation에서 만세력·궁합·결제·AI 경계·1:N·계정/정책·ESLint·Production build 전체 통과
- Day 24 릴리스 계약 테스트와 CI 연결 완료

## 출시 blocker

다음 문제만 베타 운영을 즉시 중단하거나 hotfix 대상으로 취급한다.

- 결제 성공 후 결과가 유실됨
- 동일 결제에 AI가 중복 생성되어 비용이 중복 발생함
- 다른 계정이 유료 결과를 열람할 수 있음
- 정책 동의 없이 결제가 가능함
- 개인정보·비밀값·개발자용 내부 지표가 사용자 화면 또는 외부 AI 요청에 노출됨
- 회원탈퇴 뒤 제거 대상인 계정·출생정보·리포트 원문·복구키가 남음
- 친구/직장동료 결과에 명백한 연애·성적 프레임이 섞이는 등 관계 상품이 구조적으로 잘못 생성됨
- JSON/API/저장 구조 실패로 유료 결과가 생성되지 않음

단정 표현, 상대 심리 추정, 오행→심리 해석, 문장 중복, 이름 반복, 목표 분량 편차, 횟수·시간 조언, 문체 취향 문제는 베타 운영을 막지 않는다.

## 운영 중 보완 백로그

아래 항목은 Day 24 미완료가 아니라 **post-beta 운영 QA**로 이관한다.

- 360px / 390px / 430px 실기기 전체 화면 재검증
- 1:1·1:N 운영 테스트 결제의 반복 E2E
- 비회원 결과 → 카카오 로그인 → 계정 귀속 → 보관함 재열람 반복 검증
- 결제 직후 `생성중` → `완료` 카드 전환 반복 검증
- 카카오 완료 알림 실제 수신 반복 검증
- 회원탈퇴·카카오 unlink 운영 반복 검증
- Production runtime error 및 AI 사용량·원가 관찰
- 공개 운영정보와 정식 판매용 환경값 최종 입력
- AI 문체, 재미, 단정 강도, 중복, 리포트 분량을 실제 사용자 반응에 맞춰 튜닝
- 월운 기반 월 단위 타이밍 등 베타 이후 기능 고도화

## 배포 상태 주의

최신 main의 Vercel 자동 배포가 Hobby build rate limit에 걸릴 경우 이는 코드 실패로 판정하지 않는다. 마지막 정상 Production은 유지하고, 제한이 해제된 뒤 최신 main을 Production에 반영한다. 배포 제한 자체 때문에 기능 코드를 되돌리거나 Day 24 완료 판정을 취소하지 않는다.

## Production 환경값

정식 판매 공개 전에 다음 값을 확인한다.

- `NEXT_PUBLIC_OPERATOR_NAME`
- `NEXT_PUBLIC_OPERATOR_EMAIL`
- `NEXT_PUBLIC_BUSINESS_REGISTRATION_NUMBER`
- `NEXT_PUBLIC_ECOMMERCE_REGISTRATION_NUMBER`
- `KAKAO_ADMIN_KEY`
- `KAKAO_TOKEN_ENCRYPTION_KEY`
- `NEXT_PUBLIC_APP_URL`

서버 비밀값에는 `NEXT_PUBLIC_` 접두사를 붙이지 않는다.

## 베타 기준선

Day 24 마감 커밋을 베타 기준선으로 사용한다. Git 태그를 사용할 수 있는 운영 경로에서는 `v0.1.0-beta.1` 형식으로 표시할 수 있다. 태그 생성 자체는 Day 24 기능 완료의 필수 조건으로 두지 않는다.

## 동결 후 규칙

Day 24 이후에는 별도의 날짜별 개발 일정으로 되돌아가지 않는다. 실제 사용 중 발견되는 문제를 `blocker / hotfix / improvement`로 분류하고, blocker는 즉시 수정하며 나머지는 사용자 반응과 운영 데이터를 보면서 순차 보완한다.
