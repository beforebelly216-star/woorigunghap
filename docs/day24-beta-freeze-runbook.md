# Day 24 베타 동결·출시 준비 런북

기준 브랜치: `main`
기준 Production SHA: `8b74cee33712803dad18d00893470ecb23a9ae21`

## 목적

Day 24는 새 기능을 추가하는 날이 아니라, 이미 구현된 1:1·1:N 유료 흐름을 실제 운영 환경에서 끝까지 검증하고 베타 릴리스 기준을 동결하는 단계다.

## 릴리스 게이트

아래 항목이 모두 통과하기 전에는 버전 태그를 생성하지 않는다.

- [ ] 1:1 운영 E2E: 입력 → 정책 동의 → NICE 테스트 결제 → 생성중 → 결과 완료 → 재접속·복구
- [ ] 1:N 운영 E2E: 기준자 + 후보 2~5명 → 정책 동의 → 3,000원 테스트 결제 → 비교 결과 → 재접속·복구
- [ ] 비회원 유료 결과 → 카카오 로그인 → 계정 귀속 → 보관함 → 저장 결과 재열람
- [ ] 결제 직후 보관함에 `생성중` 카드 노출 후 `완료` 카드로 전환
- [ ] 다른 카카오 계정으로 동일 결과 접근 시 차단
- [ ] 360px / 390px / 430px 실기기에서 입력·결제·결과·보관함·정책·탈퇴 화면 검증
- [ ] 카카오 완료 알림 선택동의 계정에서 실제 메시지 1회 수신
- [ ] 회원탈퇴 후 계정·세션·리포트 원문·출생정보·복구 접근정보 삭제 확인
- [ ] 법정 최소 거래기록만 분리 보존 확인
- [ ] `KAKAO_ADMIN_KEY` 설정 환경에서 카카오 unlink 성공 확인
- [ ] 1:1·1:N 생성 시간, AI 사용량, 원가 로그, 중복 생성 여부 확인
- [ ] Production 공개 운영정보 미입력 상태 제거
- [ ] Production runtime error 0건 또는 알려진 문제로 승인된 건만 존재

## 필수 Production 환경값

정식 판매 전 다음 값이 비어 있으면 베타 공개를 차단한다.

- `NEXT_PUBLIC_OPERATOR_NAME`
- `NEXT_PUBLIC_OPERATOR_EMAIL`
- `NEXT_PUBLIC_BUSINESS_REGISTRATION_NUMBER`
- `NEXT_PUBLIC_ECOMMERCE_REGISTRATION_NUMBER`
- `KAKAO_ADMIN_KEY`
- `KAKAO_TOKEN_ENCRYPTION_KEY`
- `NEXT_PUBLIC_APP_URL`

`KAKAO_TOKEN_ENCRYPTION_KEY`를 추가하거나 회전한 경우 새 Production 배포가 필요하다.

## 운영 E2E 기록 양식

각 테스트는 아래 5가지를 남긴다.

1. 테스트 시각(KST)
2. 상품(1:1 / 1:N)과 관계 유형
3. 결제 ID 또는 내부 주문 ID
4. 기대 결과 / 실제 결과
5. 실패 시 재현 절차와 스크린샷 또는 로그 위치

## 알려진 문제 관리

출시를 막지 않는 문제만 known issue로 허용한다. 다음은 반드시 blocker로 취급한다.

- 결제 성공 후 결과가 사라짐
- 동일 결제의 AI 중복 생성 또는 중복 비용 발생
- 다른 계정이 유료 결과를 열람 가능
- 계정 탈퇴 후 출생정보·리포트 원문·복구키가 남음
- 정책 동의 없이 결제 가능
- 카카오 메시지 선택동의 없이 토큰 저장 또는 메시지 전송
- 모바일에서 결제 버튼/입력 필드가 조작 불가

## 베타 동결 절차

1. `main`이 Production SHA와 일치하는지 확인한다.
2. GitHub Actions 핵심 회귀, ESLint, Production build가 모두 통과했는지 확인한다.
3. 위 운영 E2E 릴리스 게이트를 전부 마감한다.
4. 알려진 문제를 blocker / non-blocker로 분류한다.
5. Production 환경값을 최종 점검한다.
6. 릴리스 직전 main의 commit SHA를 기록한다.
7. 모든 blocker가 0개일 때만 `v0.1.0-beta.1` 형태의 베타 태그를 생성한다.

## 동결 후 규칙

베타 태그 생성 뒤에는 치명 버그 수정 외 기능 추가를 금지한다. 수정이 필요하면 별도 hotfix 브랜치와 회귀 테스트를 거쳐 새 베타 태그를 만든다.
