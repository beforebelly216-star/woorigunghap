# 우리궁합 1:N 비교 상품 구현 명세

## 목적
한 명의 기준 인물과 여러 비교 대상의 궁합을 같은 기준으로 계산해, 단순한 1:1 리포트 반복이 아니라 "누구와 어떤 관계에서 더 잘 맞는지"를 비교해 보여주는 1:N 전용 결과를 제공한다.

궁합 산식·배점·출생시간 미상 처리의 최신 기준은 [`compatibility-scoring-policy.md`](./compatibility-scoring-policy.md)를 따른다.

## 상품 기본값
- 상품키: `oneToMany`
- 가격: 3,000원
- 기준 인물: 1명
- 비교 대상: 최소 2명, 최대 5명
- 지원 관계 유형: 짝사랑 / 썸 / 연인 / 친구 / 직장동료
- 계산 프로필:
  - 짝사랑 / 썸 / 연인 → `romance`
  - 친구 → `friend`
  - 직장동료 → `coworker`
- 한 주문에서는 하나의 관계 유형만 선택한다.
- 1:N 결과는 1:1 상세 리포트를 N개 붙이는 방식이 아니라 비교·랭킹·차이 중심의 별도 포맷을 사용한다.

## 입력
### 기준 인물
- 이름 또는 별칭
- 성별
- 생년월일
- 출생시간(모름 허용)
- 양력/음력

### 비교 대상
각 대상마다 동일한 출생정보를 받는다.
- 이름 또는 별칭
- 성별
- 생년월일
- 출생시간(모름 허용)
- 양력/음력

## 계산 원칙
- 모든 대상은 동일한 만세력/궁합 계산 엔진과 동일 버전으로 계산한다.
- 동일한 사용자 관계 유형은 동일한 `romance / friend / coworker` 배점 프로필을 사용한다.
- AI는 사주 원국이나 궁합 점수를 임의 계산하지 않는다.
- 서버 계산 결과를 `calculationSnapshot`으로 고정한 뒤 AI는 설명 문장만 생성한다.
- 동일 입력과 동일 계산 버전이면 비교용 원시 점수는 재생성해도 같아야 한다.

### 출생시간 미상
- 시간 미상자를 임의 시주나 고정 중립점으로 대체하지 않는다.
- 한 명 시간 미상 시 가능한 시주 시나리오를 기본 최대 12개 계산한다.
- 두 명 모두 시간 미상 시 기본 최대 144개 조합을 계산한다.
- 입춘/절입 경계일은 경계 전후 상태를 별도 시나리오로 추가할 수 있다.
- 각 항목은 시나리오 중앙값을 대표 점수로 사용하고, 종합점수의 최저/최고를 `uncertaintyRange`로 저장한다.
- 과거의 `시간 미상자 존재 시 전원 3주×3주 강제` 규칙은 사용하지 않는다. 각 시나리오를 4주 상태로 계산해, 시간을 알고 있는 후보의 시주 정보를 버리지 않는다.

## 9항목 배점 프로필
상세 산식은 `compatibility-scoring-policy.md`를 기준으로 한다.

| 항목 | romance | friend | coworker |
|---|---:|---:|---:|
| 일간 상성 | 10 | 15 | 15 |
| 일지 상성 | 15 | 5 | 5 |
| 용신·기신 부합도 | 20 | 20 | 20 |
| 오행 상보성 | 10 | 15 | 20 |
| 천간 합충 | 10 | 15 | 10 |
| 지지 형충파해 | 15 | 15 | 15 |
| 신살·귀인·공망 | 5 | 10 | 10 |
| 배우자성 실체화 | 10 | 0 | 0 |
| 대운 동조 | 5 | 5 | 5 |
| **합계** | **100** | **100** | **100** |

관계유형별 처리는 별도 보너스 점수를 더하는 방식이 아니라, 동일한 명리 근거를 관계 목적에 맞게 100점 안에서 재배분하는 방식이다.

## 공통 비교 지표
각 대상에 대해 사용자 친화적인 비교 지표를 0~100으로 정규화해 보여줄 수 있다. 이 지표는 9항목 원시 산식을 대체하지 않고 표시용 projection으로 사용한다.

1. 종합 궁합
2. 소통 궁합
3. 정서 궁합
4. 갈등/마찰 적합도
5. 지속성·안정성

관계 유형별 추가 지표:
- 짝사랑 / 썸 / 연인: 끌림/연애 텐션, 생활 궁합
- 친구: 편안함, 신뢰/의리
- 직장동료: 협업 효율, 역할 보완성

### Day 15 표시용 6개 요약 지표
- `overall`: 서버 최종 종합점수
- `communication`: 일간 상성 + 천간 합충의 평균
- `emotionalStability`: 일지 상성 + 용신·기신 부합도의 평균
- `conflictManagement`: 천간 합충 + 지지 형충파해의 평균
- `longTerm`: 용신·기신 부합도 + 오행 상보성 + 대운 동조의 평균
- `relationshipPurpose`: romance는 일간·일지·배우자성, friend는 일간·오행·신살, coworker는 일간·오행·천간·지지의 평균

요약 지표는 `one-to-many-view-v1.0.0`의 표시용 projection이다. 종합 순위나 결제·저장 스냅샷의 9개 원시 점수를 대체하지 않는다. 결과 화면은 요약 지표를 먼저 보여주고, 9개 상세 점수는 접힌 분석 근거 영역에 둔다.

## 1:N 결과 화면 구성
### 1. 한눈에 보는 순위
- 종합 점수 기준 1위~N위
- 대상별 종합점수
- 관계 유형에 맞춘 한 줄 요약
- 점수 차이가 작으면 과도한 우열 표현을 피하고 "비슷한 수준"으로 표시
- 시간 미상으로 `uncertaintyRange`가 크게 겹치면 단일 점수 우열을 과장하지 않는다.

### 2. 비교 매트릭스
행: 비교 대상
열: 공통 지표 + 관계 유형별 추가 지표

사용자는 어떤 사람이 어떤 영역에서 강한지 한 화면에서 볼 수 있어야 한다.

### 3. 대상별 강점/주의점
각 대상마다:
- 가장 잘 맞는 포인트 2개
- 가장 부딪히기 쉬운 포인트 1~2개
- 관계를 잘 굴리는 실용 팁 1개

### 4. 상황별 추천
점수 하나로 전체 관계를 결정하지 않고 상황에 따라 구분한다.
예:
- 대화가 가장 편한 사람
- 감정적으로 안정적인 사람
- 오래 가기 좋은 사람
- 갈등 관리가 쉬운 사람
- 관계 유형별 핵심 목적에 가장 잘 맞는 사람

각 상황의 표시용 지표 최고점을 서버가 찾는다. 최고점과 0~2점 차이이거나 두 후보의 종합 `uncertaintyRange`가 겹치면 한 명을 강제로 고르지 않고 공동 추천한다. AI는 서버가 확정한 추천 후보 배열을 추가·삭제·재정렬할 수 없다.

### 5. 최종 비교 요약
- 종합 1위
- 각 대상이 특히 좋은 상황
- 기준 인물이 관계에서 주의할 공통 패턴
- "누가 절대적으로 더 좋은 사람"이라는 표현은 금지하고 궁합 맥락으로 한정

## 랭킹 규칙
- 기본 랭킹은 서버 계산 종합점수로 결정한다.
- AI가 순위를 변경할 수 없다.
- 동점 또는 근소 차이 정책:
  - 0~2점 차이: 사실상 동급
  - 3~5점 차이: 근소 우세
  - 6점 이상: 의미 있는 차이
- 화면에 점수와 순위를 함께 제공하되, 근소 차이를 과장하지 않는다.
- `uncertaintyRange`가 겹치는 후보는 차이가 확정적인 것처럼 서술하지 않는다.
- 0~2점 동급 그룹은 그룹 최고점을 기준으로 묶는다. 연쇄 비교로 3점 이상 떨어진 후보가 같은 그룹에 포함되지 않게 한다.
- 동급 후보의 표시 순서는 입력 순서로 고정하며, 다음 순위는 공동 순위 인원만큼 건너뛴다. 예: 1위·1위·3위.
- 불확실성 범위 겹침은 순위를 바꾸지 않지만, 확정적 우열 문구 사용을 금지하는 경고로 저장한다.

## Day 14 비교 계산 JSON
- `candidate_1`부터 입력 순서 기반 익명 ID를 부여한다.
- 원본 이름·생년월일시는 계산 JSON에 포함하지 않는다.
- 후보별 1:1 `calculationSnapshot`, 서버 순위 그룹, 선두와의 점수 차이, 불확실성 범위 겹침을 고정한다.
- 비교 매트릭스는 9항목 정규화 점수를 담고, 종합 순위는 최종 정수 점수만 사용한다.
- `scoreMutableByAi=false`, `rankingMutableByAi=false`, `explanationOnly=true`를 저장한다.

## Day 15 AI 서술 계약
AI 호출 시 원본 이름/생년월일시 대신 서버가 만든 익명화된 대상 ID와 최소 계산 근거만 전달한다.

- AI payload에는 `candidate_1` 같은 입력 순서 기반 익명 ID, 서버가 확정한 순위·점수·점수 차이·불확실성 범위·9항목 표시 점수·강점/주의 축만 넣는다.
- 이름/별칭, 성별, 양·음력 구분, 생년월일·출생시간, 주문/결제 ID, 세부 원시 evidence는 넣지 않는다.
- 후보 ID와 사용자 별칭의 대응은 결제 뒤 결과 화면에서만 서버 주문 스냅샷을 이용해 적용한다.
- AI가 순위·점수·동점 그룹을 변경할 수 없으며, `0~2점 동급` 또는 불확실성 범위 중첩 후보에는 확정적 우열 표현을 금지한다.
- 출력 JSON은 순위 요약, 후보별 한 줄·강점 2개 이상·주의점 1개 이상·실용 팁, 소통/정서 안정/장기 지속/갈등 관리/관계 목적별 단일·공동 추천, 최종 비교 요약으로 고정한다.
- 문체는 `결론 → 계산 근거 → 관계에서의 체감 → 실행할 행동` 순서를 지키고, 미래 예언·상대의 속마음 단정·"누가 더 좋은 사람"이라는 표현을 금지한다.

예시 출력 JSON 구조:
```json
{
  "rankingSummary": {
    "headline": "...",
    "summary": "...",
    "closenessNotice": "..."
  },
  "candidates": [
    {
      "candidateId": "candidate_1",
      "oneLine": "...",
      "strengths": ["...", "..."],
      "cautions": ["..."],
      "practicalTip": "..."
    }
  ],
  "situationalRecommendations": {
    "communication": { "candidateIds": ["candidate_1", "candidate_2"], "reason": "..." },
    "emotionalStability": { "candidateIds": ["candidate_1"], "reason": "..." },
    "longTerm": { "candidateIds": ["candidate_1", "candidate_3"], "reason": "..." },
    "conflictManagement": { "candidateIds": ["candidate_2"], "reason": "..." },
    "relationshipPurpose": { "candidateIds": ["candidate_1"], "reason": "..." }
  },
  "finalSummary": "..."
}
```

- 계산 프로필

- 대상별 9항목 점수

- 랭킹 결과
- AI 모델명
- 프롬프트 버전

- 생성 시각

## Day 16 결제·생성·복구 계약

- 상품키는 `oneToMany`, 금액은 3,000원으로 1:1 주문과 분리한다.
- 주문 생성 시 원본 접근 토큰은 브라우저에만 전달하고 서버에는 SHA-256 해시만 저장한다.
- 결제 `customData`에는 표시 이름을 제외한 입력 해시와 바인딩 버전을 저장한다. 후보 순서는 익명 후보 ID 연결의 일부이므로 해시에 포함한다.
- 결과 API는 브라우저가 다시 보낸 생년월일시를 신뢰하지 않고, 접근 토큰으로 확인한 서버 주문 스냅샷만 사용한다.
- PortOne 서버 조회에서 `PAID`, 상품키, 3,000원, 입력 해시가 모두 일치한 뒤에만 계산과 AI 생성을 시작한다.
- 후보별 AI 호출을 하지 않는다. 모든 후보의 익명 계산 근거를 한 번에 묶어 1개의 비교 해설 JSON을 생성한다.
- DB의 `generation_status`를 원자적으로 선점해 동일 결제의 동시 요청이 AI를 중복 호출하지 않게 한다. 중단된 선점은 5분 뒤에만 회수할 수 있다.
- 계산 스냅샷, AI JSON, 모델명, 프롬프트/페이로드 버전, 사용량 메타를 한 결과 스냅샷으로 저장한다.
- 재접속 시 URL fragment의 접근 토큰을 POST 복구 API로 보내며, 완료된 저장본을 다시 생성하지 않고 그대로 반환한다.
- PortOne 웹훅은 서명 검증 후 웹훅 ID를 먼저 저장하고, 중복 이벤트는 재처리하지 않는다. 승인 상태와 금액은 PortOne 서버 조회 결과만 신뢰한다.

## MVP 구현 범위
포함:
- 기준 1명 + 대상 2~5명
- 짝사랑 / 썸 / 연인 / 친구 / 직장동료
- 종합 랭킹
- 비교 매트릭스
- 대상별 강점/주의점
- 상황별 추천
- AI 또는 템플릿 기반 설명

MVP에서 제외:
- 6명 이상 대규모 비교
- 그룹 전체의 집단 사주 분석
- 대상끼리의 N:N 상호 궁합
- 시간 흐름에 따른 월별/연도별 랭킹 변화
- 짝사랑·썸·연인 각각의 별도 점수 가중치 엔진 (Day 15 이후 백로그)

## 구현 완료 조건
다음 조건을 만족하면 1:N 기능을 구현 완료로 본다.
1. 2~5명의 입력을 검증할 수 있다.
2. 각 대상의 1:1 계산을 동일 엔진으로 수행한다.
3. 사용자 관계 유형에 맞는 계산 프로필을 적용한다.
4. 서버에서 비교 점수와 랭킹을 결정한다.
5. 시간 미상자의 시주 시나리오와 불확실성 범위를 공정하게 처리한다.
