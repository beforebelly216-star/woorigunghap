## IAP 지급과 복구

- 공식 주문 조회 API는 **서버 인증된 userKey를 `x-toss-user-key` 헤더에 포함하면 해당 사용자의 주문만 조회**한다고 명시합니다. 2026-10-05 확인: https://developers-apps-in-toss.toss.im/documentation/common/monetization/iap/in-app-purchase (주문 상태 조회 API).
- `POST /api/toss/iap/grant`: 로그인 계정의 providerUserId만 헤더로 전달합니다. 요청의 사용자/수량은 지급 근거로 쓰지 않습니다. orderId·등록 SKU·PAYMENT_COMPLETED/PURCHASED 검증 후 서버 설정 수량을 영구 원장에 지급합니다. REFUNDED/NOT_FOUND/진행 중/다른 SKU는 거절합니다.
- 지급 reference는 소문자 정규화한 주문 UUID입니다. 같은 주문 반복/미결 복구는 중복 지급되지 않습니다. 다른 계정 또는 다른 수량과 충돌하면 실패합니다. 기존 SKU의 지급 수량은 출시 후 임의 변경하지 않습니다.
- DB 지급 확인 이후에만 `productGranted:true`를 반환합니다. 불확실 commit 응답은 SDK 지급 완료로 인정하지 않고 동일 주문 재조회로 복구합니다. 상태 진단 API의 scope는 `authenticated_user_order`이며 지급은 하지 않습니다.
- 화면 상품명/가격은 `IAP.getProductItemList()`의 등록 상품 정보를 표시합니다. 결제 버튼은 사용자 선택 이후에만 SDK를 실행합니다. 로그인 후 미결 주문 복구와 보관함의 수동 복구가 영구 지급 성공 뒤 `completeProductGrant`를 호출합니다. 실제 구매는 테스트하지 않았습니다.
- **이미 지급된 주문의 사후 환불을 지갑과 사용한 권한에 반영하는 주문별 사용량 배분/회수는 미구현**입니다. 사용한 재화/대기 예약/새 충전의 환불 정산, 결과 보관·탈퇴 정책, 실제 결제 성공·서버 지급 실패·복구·환불 QA 전에는 유료 기능을 켜면 안 됩니다.
