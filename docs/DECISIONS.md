# 우리사주 주요 결정 기록

> GPT와 Claude가 다시 논의하지 말아야 할 확정사항. 변경하려면 사용자 지시 또는 명확한 운영 근거가 필요하다.

## 브랜드

- 공식 프로젝트명/서비스명: **우리사주**
- 이전 브랜드명은 새 사용자 노출 카피, 결제 상품명, 정책, 채널 메시지, SEO/metadata에서 사용하지 않는다.
- GitHub 저장소 `beforebelly216-star/woorigunghap`, 기존 Vercel 도메인, DB 테이블명/저장 버전의 `woorigunghap_*` 같은 기술 식별자는 기존 구매 데이터와 배포 연결 호환을 위해 별도 마이그레이션 전까지 레거시 내부 식별자로 유지할 수 있다.

## 제품/가격

- 1:1: 1,000원
- 1:N: 3,000원
- 1:N은 핵심 상품 범위이며 제거하지 않는다.
- 관계 유형: 짝사랑 / 썸 / 연인 / 친구 / 직장동료
- 짝사랑·썸·연인은 계산상 `romance` 프로필을 공유할 수 있으나 서술/행동 조언은 관계 단계별로 분리한다.
- **신규 유입 홈은 free-first 구조를 기본으로 한다.** 첫 화면의 1순위 CTA는 `무료로 내 관계 성향 보기`이며 유료 가격은 무료 자기 분석 설명 뒤 전환 구간에서 명확하게 안내한다.
- 무료 자기 분석은 한 사람의 기존 deterministic 만세력과 60일주 캐릭터 편집 레이어만 사용한다. 주문·결제·유료 AI 생성·유료 궁합 점수/장문 리포트를 만들지 않는다.
- 무료 자기 분석은 관계 강점 / 사람을 읽는 장면 / 꼬이기 쉬운 지점 / 잘 맞는 관계 리듬의 4개 짧은 insight를 기본으로 한다.
- 무료 결과를 본 뒤에만 1:1 1,000원 / 1:N 3,000원 전환 CTA를 노출한다. 무료 입력의 본인 정보는 같은 브라우저 세션에서 1:1 첫 번째 사람으로 이어받을 수 있으나 원본 생년월일시를 URL query에 넣지 않는다.

## UI / 디자인

- **`docs/DESIGN_FIVE_ELEMENT_SYSTEM.md`의 `우리사주 Design Foundation v2`를 전체 UI/UX의 단일 디자인 기준점으로 사용한다. (2026-08-25 사용자 재확정)** 기존 라벤더 파스텔 및 초기 오행 스펙은 이 문서로 대체한다.
- 포지셔닝은 전통 사주/운세 사이트가 아니라 **현대적인 관계 분석 제품**이다. 외부 레퍼런스는 원리만 참고하며 고유 화면·카피·그래픽을 복제하지 않는다.
- 시각 문법은 **neutral canvas + 실제 데이터에 연결된 오행 기능색 + 강한 타이포그래피 + 단계적 정보 위계**를 기본으로 한다.
- 오행 5색은 실제 오행 비중·태그·계산 정보가 있을 때만 사용하며 장식용 CTA 색, 관계유형 고정색, 전체 배경색으로 쓰지 않는다.
- Primary CTA는 별도 장식색 대신 ink 계열을 기본으로 하고, 성공/경고/오류 semantic color는 오행색과 의미를 분리한다.
- 입력/결제 flow는 `compact 480px`, 1:1 리포트는 `report 640px`, 1:N 비교는 `compare 960px`을 기준 최대 폭으로 사용한다. **모든 화면을 PC까지 480px로 강제하는 방식은 디자인 원칙에서 폐기한다.** 기존 강제 CSS는 화면별 개편 과정에서 안전하게 제거한다.
- 카드형 박스 남용, 큰 그림자, glassmorphism, 장식 gradient/glow를 기본 스타일로 사용하지 않는다. 정보 위계는 타이포·여백·얇은 border를 우선한다.
- 다크모드는 지원하지 않는다. 라이트 팔레트 단일 구성으로 유지한다.
- 홈에서 계산/AI/결제 구현 원칙을 설명하는 범용 trust 카드와 면책성 장문 문구는 전환에 도움이 되지 않는 경우 노출하지 않는다.

## 리포트

- 1:1은 CH0~CH9 상세 리포트 구조를 기본으로 유지한다.
- 목표 분량은 대체로 5,000~8,000자, 필요 시 약 10,000자까지 허용한다.
- 사용자 재미를 해치지 않는 범위에서 지나치게 보수적인 문장 검수는 피한다.
- 문체 취향, 재미, 일부 반복/분량 편차는 그 자체로 출시 blocker가 아니다.
- 법적·개인정보·결제·권한·저장 실패 수준의 문제를 우선한다.
- 유료 리포트는 **일상 언어의 관계 결론/장면 → 사주 용어와 계산 근거** 순서로 설명한다.
- 계산 근거가 충분한 내용은 결론형 문장으로 분명하게 쓰되, 서버 근거 없는 사실·숫자·미래 시기·내부 심리 원인은 새로 만들지 않는다.
- `서버가 제공한`, `서버 계산상`, `strongest`, `weakest` 같은 구현 표현을 사용자 문장에 노출하지 않는다.
- 1:N은 후보 이름/의미형 제목을 우선하고 `첫 번째/두 번째`, `강점 1/2` 같은 순번형 본문 표현을 피한다.
- 1:N 사용자 언어는 **연락·대화 / 갈등과 회복 / 신뢰 / 생활 리듬 / 장기관계**처럼 실제 체감 장면을 우선한다.
- 유료 1:1의 기본 화자는 **사주소년**이다. 독립적인 소년 탐험가 캐릭터로 운영하며 특정 기존 작품의 고유명사·인물·주문·대사·문체를 직접 모사하지 않는다.
- CH2의 `그 사람의 속마음`은 실제 내면을 맞힌다고 주장하는 기능이 아니라 계산된 관계 반응을 1인칭 가상 독백으로 번역하는 편집 장치다.
- 1:1 궁합 유형과 60일주 캐릭터는 기존 서버 계산 snapshot을 쉽게 설명하는 편집 레이어이며 점수·합충·용신·미래 시기·숨은 심리를 새로 결정하지 않는다.
- 결과 UX는 **점수/한 줄 관계 정의 → 핵심 지표 → Relationship Label → Two Sides → 강점/주의점 → 관계 흐름 → 행동 가이드 → CH0~CH9 상세 리포트 → 공유/다음 행동**의 progressive disclosure를 기본으로 한다.
- 1:N은 1:1 결과를 후보 수만큼 반복하지 않고 **전체 ranking → 후보 역할 → 공통 지표 비교 → 후보별 강점/주의점 → 상세 후보 리포트** 순으로 비교 의사결정을 돕는다.
- 결제 전 유료 콘텐츠는 CSS blur로 숨기지 않고 실제 유료 AI 본문 대신 기능 예고만 표시한다.

## 공유 / 그로스

- 전체 Growth 퍼널은 `무료 자기 분석 → Aha → 유료 궁합 시작 → 유료 결과 → 공유 → 상대 반응 → Shared View → 신규 궁합 시작`을 기본으로 한다.
- 무료 자기 분석 API는 결과 DTO에 원본 생년월일시, 전체 명식 snapshot, 유료 상세 본문, 결제/접근 식별자를 반환하지 않는다.
- 공유 카드에는 전체 점수·궁합 유형·관계 유형·짧은 요약 정도만 노출하고 생년월일시·세부 명식·장문 유료 본문·결과 접근 토큰은 포함하지 않는다.
- 현재 유료 결과 접근 URL/accessToken을 공유하지 않는다.
- **카카오 전용 메시지/공유 API는 사용하지 않는다.** 공유는 Web Share API, 이미지 저장, 일반 공유 URL 등 플랫폼 중립 방식으로 구현한다.
- Shared View는 전체 유료 리포트를 무료 공개하지 않고 공유 전용 데이터만 제공한다.
- 유료 결과 화면에서는 1:1·1:N 모두 실제 공유 UI를 제공해야 하며, 보관함의 완성 결과 CTA에서도 공유 가능 결과임을 명확히 안내한다.

## 계산/AI 경계

- 사주/궁합 계산은 서버 결정론 로직이 수행한다.
- AI는 계산 결과를 바꾸지 않고 서술만 생성한다.
- 내부 결정론적 계산 근거는 기존 9개 차원과 `rawTotal` 가중합이다.
- 사용자 공개 종합점수는 raw 30~100을 45~100으로 단조 보정해 사용하며 후보 순서의 계산 근거를 임의로 바꾸지 않는다.
- 공개 점수 구간 라벨은 관계 체감을 돕는 제품 표현이며 성공확률·미래 예측 확률이 아니다.
- 이름/원본 생년월일시는 외부 AI에 직접 전달하지 않는다.
- 결제가 서버에서 검증된 뒤에만 유료 AI 생성을 실행한다.
- 동일 결제/세그먼트 AI 중복 호출을 막는 single-flight/idempotency 원칙을 유지한다.
- 1:1의 `intro` / `dynamics` / `action`은 서로 독립된 single-flight lock을 유지하면서 가능한 경우 병렬 생성·복구한다. 순차 대기로 세 묶음의 최대 시간이 합산되는 구조를 다시 만들지 않는다.

## 저장/계정/보안

- 서버 DB(Neon)가 주문·결제·완성 결과의 권위 데이터다.
- 브라우저 저장소는 재개/복구 보조 사본이다.
- 무료 자기 분석의 1:1 이어받기 정보는 같은 브라우저 `sessionStorage`의 임시 UX 보조 사본이며 서버 구매 데이터가 아니다.
- 결과 접근 토큰 원문은 서버에 저장하지 않고 SHA-256 해시를 사용한다.
- Kakao 로그인은 선택형이며 비회원 결제 흐름을 유지한다.
- 계정 소유권 검증 없이 유료 결과를 열람하게 만들지 않는다.
- 회원탈퇴 시 제거 대상 데이터 삭제 및 필요한 경우 Kakao unlink를 유지한다.
- 사용자는 계정 보관함의 완성된 개별 구매 결과를 영구 삭제할 수 있다. 상세 리포트·입력 개인정보·접근 토큰/브라우저 복구 사본을 제거하고 재생성을 허용하지 않는다. 법정 보존 의무가 있는 최소 결제기록은 해당 범위에서 유지할 수 있다.
- 비밀값은 GitHub/브라우저 코드에 넣지 않는다.

## 카카오 로그인 / 메시지 기능

- **카카오 로그인은 계정 인증·구매 결과 귀속·보관함 이용 목적에만 사용한다.**
- **Kakao Developers `talk_message` / `나에게 보내기` 기능은 사용하지 않는다.** OAuth에서 해당 scope를 요청하지 않고 메시지 전송용 access/refresh token을 별도 저장하지 않는다.
- **카카오톡 채널/플러스친구 알림톡 및 SOLAPI 발송 기능은 사용하지 않는다.**
- 완료 알림을 위한 휴대전화 번호를 수집·저장하지 않는다.
- 결과 생성 완료 상태는 결과 화면과 계정 보관함의 서버 상태를 통해 확인한다.
- 과거 실험으로 생성된 DB 컬럼/테이블이 존재할 수 있으나 애플리케이션은 더 이상 읽거나 쓰지 않는다. 물리적 schema 삭제는 기존 계정 데이터에 영향이 없는지 확인한 별도 migration으로만 수행한다.
- 이 메시지/알림 기능을 다시 도입하려면 사용자 명시 지시와 비용·신뢰성·개인정보 검토가 선행되어야 한다.

## 개발/배포

- 기본 브랜치와 단일 진실 공급원은 GitHub `main`이다.
- 의미 있는 변경은 테스트 후 커밋/푸시하고 상태 문서를 갱신한다.
- GitHub connector 또는 로컬 git 등 실제 쓰기 권한이 있는 환경에서만 원격 변경을 수행한다. 특정 모델/클라이언트가 항상 쓰기 권한을 가진다고 가정하지 않는다.
- **Vercel Git 자동 배포는 비활성화한다. `vercel.json`의 `git.deploymentEnabled=false`를 유지한다.**
- **코드의 `main` 병합과 Vercel Preview/Production 배포는 별도 단계다. Vercel 배포는 해당 배포 배치에 대해 사용자가 명시적으로 승인한 뒤에만 실행한다.**
- Vercel Hobby build rate limit은 코드 실패가 아니며, 이 이유만으로 정상 코드를 revert하지 않는다.
- 관련 코드/테스트/상태 문서는 가능한 한 한 작업 배치로 묶고 원격 `main` 갱신은 한 번으로 한다.
- Day 24 이후 날짜별 개발 일정으로 되돌아가지 않는다. 운영 이슈를 `blocker / hotfix / post-beta 운영 QA / improvement`로 분류한다.

## AI 교대 작업 규칙

- GPT와 Claude는 채팅 기록을 공유한다고 가정하지 않는다.
- 작업 시작 시 `AGENTS.md` → `docs/PROJECT_STATE.md` → `docs/NEXT_TASK.md` → `docs/DECISIONS.md` 순서로 읽는다.
- 이전 모델이 남긴 미완료 작업이 있으면 그 지점부터 이어간다.
- 이미 완료된 기능을 스타일 취향만으로 대규모 재작성하지 않는다.
- 사용자 지시가 상태 문서와 충돌하면 최신 사용자 지시를 우선하고 상태 문서를 즉시 갱신한다.
- 같은 파일을 GPT와 Claude가 동시에 편집하는 병렬 작업을 피한다.
