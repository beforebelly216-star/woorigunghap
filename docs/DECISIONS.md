# 우리사주 주요 결정 기록

> GPT와 Claude가 다시 논의하지 말아야 할 확정사항. 변경하려면 사용자 지시 또는 명확한 운영 근거가 필요하다.

## 브랜드

- 공식 프로젝트명/서비스명: **우리사주**
- 이전 브랜드명은 새 사용자 노출 카피, 결제 상품명, 정책, 채널 메시지, SEO/metadata에서 사용하지 않는다.
- GitHub 저장소 `beforebelly216-star/woorigunghap`, 기존 Vercel 도메인, DB 테이블명/저장 버전의 `woorigunghap_*` 같은 기술 식별자는 기존 구매 데이터와 배포 연결을 깨뜨릴 수 있어 별도 마이그레이션 전까지 레거시 내부 식별자로 유지할 수 있다.
- 레거시 기술 식별자는 사용자에게 서비스명으로 노출하지 않는다.

## 제품/가격

- 1:1: 1,000원
- 1:N: 3,000원
- 1:N은 핵심 상품 범위이며 제거하지 않는다.
- 관계 유형: 짝사랑 / 썸 / 연인 / 친구 / 직장동료
- 짝사랑·썸·연인은 계산상 `romance` 프로필을 공유할 수 있으나 서술/행동 조언은 관계 단계별로 분리한다.

## 리포트

- 1:1은 CH0~CH9 상세 리포트 구조를 유지한다.
- 목표 분량은 대체로 5,000~8,000자, 필요 시 약 10,000자까지 허용한다.
- 사용자 재미를 해치지 않는 범위에서 지나치게 보수적인 문장 검수는 피한다.
- 단정 표현, 상대 심리 추정, 오행→심리 해석, 일부 반복/분량 편차는 그 자체로 출시 blocker가 아니다.
- 법적·개인정보·결제·권한·저장 실패 수준의 문제를 우선한다.
- 유료 리포트의 기본 서술 순서는 **일상 언어로 관계에서 체감할 결론/장면을 먼저 설명하고, 이어서 사주 용어와 계산 근거로 왜 그런 해석이 나왔는지 설명**하는 방식으로 한다.
- 사용자 문장에는 `서버가 제공한`, `서버 계산상`, `strongest`, `weakest` 같은 구현 세부사항·내부 필드명을 노출하지 않는다.
- 1:N 비교에서는 `첫 번째/두 번째/세 번째`, `강점 1/2/3` 같은 순번형 명명을 피하고 후보 이름 또는 의미가 드러나는 제목을 사용한다.

## 계산/AI 경계

- 사주/궁합 계산은 서버 결정론 로직이 수행한다.
- AI는 계산 결과를 바꾸지 않고 서술만 생성한다.
- 원본 이름/생년월일시/알림용 휴대전화 번호를 AI에 직접 전달하지 않는다.
- 결제가 서버에서 검증된 뒤에만 유료 AI 생성을 실행한다.
- 동일 결제/세그먼트 AI 중복 호출을 막는 single-flight 원칙을 유지한다.
- AI에 원본 개인정보를 늘리지 않는 범위에서 이미 서버가 계산한 일주/일간, 오행 균형, 합충·상호작용, 용신 관련 안전 신호 등은 사용자가 납득할 수 있는 근거를 만드는 데 필요한 만큼 제공할 수 있다.

## 저장/계정/보안

- 서버 DB(Neon)가 주문·결제·완성 결과의 권위 데이터다.
- 브라우저 저장소는 재개/복구 보조 사본이다.
- 결과 접근 토큰 원문은 서버에 저장하지 않고 SHA-256 해시를 사용한다.
- Kakao 로그인은 선택형이며 비회원 결제 흐름을 유지한다.
- 계정 소유권 검증 없이 유료 결과를 열람하게 만들지 않는다.
- 회원탈퇴 시 제거 대상 데이터 삭제 및 필요한 경우 Kakao unlink를 유지한다.
- 비밀값은 GitHub/브라우저 코드에 넣지 않는다.

## 카카오톡 완료 알림

- 결과 완료 알림은 Kakao Developers의 OAuth `나에게 보내기`를 주 전송수단으로 사용하지 않는다.
- 자동 정보성 완료 안내는 **우리사주 카카오톡 채널의 알림톡**으로 발송한다.
- 현재 공식 딜러사 연동 구현은 SOLAPI REST API를 사용한다.
- 알림톡은 사용자가 직접 등록한 휴대전화 번호를 기반으로 발송한다.
- 휴대전화 번호 저장/알림 발송은 선택이며 명시적 동의를 받아야 한다.
- 번호는 AES-256-GCM으로 암호화 저장하고 사용자 화면에는 마스킹만 노출한다.
- 번호는 AI에 전달하거나 서버 로그에 기록하지 않는다.
- 알림 해제 시 저장된 번호와 동의 상태를 삭제한다.
- 알림톡 템플릿은 카카오 사전 승인된 정보성 정적 템플릿을 사용한다.
- 알림톡 실패 시 SMS/LMS 자동 대체발송은 하지 않는다.
- payment 단위 idempotency를 유지해 완료 알림 중복 발송을 막는다.

## 개발/배포

- 기본 브랜치와 단일 진실 공급원은 GitHub `main`이다.
- 의미 있는 변경은 테스트 후 커밋/푸시하고 상태 문서를 갱신한다.
- Vercel은 `main` Production 자동 배포를 기본으로 한다.
- Vercel Hobby build rate limit은 코드 실패가 아니며, 이 이유만으로 정상 코드를 revert하지 않는다.
- 관련 코드/테스트/상태 문서는 가능한 한 한 작업 배치에서 정리하고 원격 `main` push는 한 번으로 묶는다.
- Day 24 이후 날짜별 개발 일정으로 되돌아가지 않는다. 운영 이슈를 `blocker / hotfix / post-beta 운영 QA / improvement`로 분류한다.

## AI 교대 작업 규칙

- GPT와 Claude는 채팅 기록을 공유한다고 가정하지 않는다.
- 둘 다 작업 시작 시 `AGENTS.md`, `PROJECT_STATE.md`, `NEXT_TASK.md`, `DECISIONS.md`를 읽는다.
- 이전 모델이 남긴 미완료 작업이 있으면 그 지점부터 이어간다.
- 이미 완료된 기능을 스타일 취향만으로 대규모 재작성하지 않는다.
- 사용자 지시가 상태 문서와 충돌하면 최신 사용자 지시를 우선하고 상태 문서를 즉시 갱신한다.
- 한 모델이 작업 중인 동안 다른 모델이 같은 파일을 동시에 편집하는 병렬 작업을 피한다.
