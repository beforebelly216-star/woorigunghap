# 우리사주 주요 결정 기록

> GPT와 Claude가 다시 논의하지 말아야 할 현재 확정사항. GitHub 최신 `main`과 최신 사용자 지시가 최우선이다.

## 브랜드

- 공식 서비스명: **우리사주**.
- 저장소명, 기존 Vercel 도메인, DB 테이블/저장 버전의 `woorigunghap_*` 등 기술 식별자는 호환성을 위해 유지할 수 있다.
- 레거시 기술 식별자를 사용자 화면의 브랜드명으로 새로 노출하지 않는다.

## 제품/가격

- 1:1: **1,000원**.
- 링크형 1:N 인연 네트워크: **무료**, 최대 12명.
- 기존 3,000원 1:N은 신규 주문을 중단하되 과거 구매 결과·복구·공유·저장 호환을 유지한다.
- 관계 유형: 짝사랑 / 썸 / 연인 / 친구 / 직장동료.
- 기존 `/free` 관계 성향 자기분석 상품/UI/API는 폐기한다.
- `/free`는 **무료 내 천생연분 보기** 입력·결과 플로우다.
- 홈 진입 카드는 `이상형 찾기 → 1:N 궁합 보기 → 1:1 궁합 보기` 순서를 기본으로 한다.

## 궁합 점수 — 2026-08-27 재확정

- 공개 종합 궁합점수의 절대 범위는 **최저 30점 / 최대 100점**이다.
- **100점 절대 상한은 반드시 유지**한다. 100점을 초과하는 결과는 허용하지 않는다.
- 관계유형별 별도 최대점 상한은 사용하지 않는다. 모든 관계가 동일한 30~100 척도를 사용하고 계산상 100점까지 도달 가능해야 한다.
- 5개 관계유형은 같은 9개 계산 차원을 사용하되 **관계에 따라 최종 가중치를 다르게 적용**한다.
- 다섯 관계가 공통으로 도달 가능한 deterministic raw 구간을 공개 30~100에 선형 정규화한다.
- 이 정규화는 재미를 위한 숨은 가점이 아니다. 낮은 raw 결과는 공개점수에서 더 낮아질 수 있다.
- 절대 30/100 경계 밖은 각각 30/100으로 clamp한다.
- AI는 점수·순위를 변경할 수 없다.

## 무료 천생연분 결과 — 2026-08-27 확정

- 기존 만세력 원국을 사용한 결정론 계산으로 생성하며 외부 AI와 유료 결제를 사용하지 않는다.
- 비교 대상이 없는 단일 사주 결과에 `천생연분 지수`, 궁합 확률, 임의 퍼센트를 표시하지 않는다.
- 결과 첫 핵심 정보는 사주팔자 전체 원국이다. 이후 `일간 / 성향 키워드 / 강점 / 보완점`을 보여준다.
- 10개 일간을 내부 비교하고 유의미한 추천 일간만 TOP 2~3으로 노출한다.
- 추천 근거는 일간 생극 관계, 원국의 오행 분포, 음양 보완, 일지 합충 관계를 함께 사용한다.
- 현재 용신 모듈은 `EVIDENCE_ONLY`이므로 용신을 확정적으로 판정하거나 용신 기반 확률을 만들지 않는다.
- 심화 결과는 `오행 구성 / 음양 균형 / 있으면 좋은 천간 / 있으면 좋은 지지 / 특히 잘 맞는 조건 / 조심해야 할 구성`을 포함한다.
- `만남 & 관계 가이드`, `인연 시기 흐름`, 추천 활동, 추천 컬러는 넣지 않는다.
- 마지막에는 주토피 해설과 `1:1 궁합 분석하기` CTA를 둔다.

## 1:1 유료 리포트 — 2026-08-27 재설계 기준

- 기존 결과 UI/UX는 새 390px 모바일 결과 디자인으로 전면 교체한다. 과거 CH/UI 문서는 계산·저장·보안 계약 외에는 새 결과 명세의 기준으로 사용하지 않는다.

## 무료 1:N 인연 네트워크 — 2026-09-01 확정

- 방장은 자기 정보만 입력해 링크를 만들고, 각 참여자는 자기 정보만 직접 입력한다.
- 최대 12명과 모든 참여자 쌍을 기존 결정론 1:1 엔진의 친구·지인 기준으로 계산한다.
- 인물 네트워크의 노드와 관계선을 통해 방장-참여자뿐 아니라 참여자 상호 간 총점도 조회한다.
- 공개 등급은 E 30~49 / D 50~59 / C 60~69 / B 70~79 / A 80~89 / S 90~100이다. S/E가 실제 계산으로 도달 가능해야 하며 방별 강제 분포 보정은 하지 않는다.
- 무료 네트워크에는 외부 AI·결제·유료 서술을 사용하지 않는다.
- 방 식별자, 방장 권한, 참여자 삭제 권한은 분리하고 권한 원문은 서버에 저장하지 않는다.
- 한 사람이 참여한 브라우저에서도 다음 사람이 직접 동의·입력해 계속 연결할 수 있다. 브라우저에는 해당 기기에서 입력한 복수 참여자의 삭제 자격을 함께 보존한다.
- 방장이 만든 네트워크는 같은 브라우저 목록에 30일 만료 시점과 함께 저장하고 1:N 시작 화면과 계정 보관함 양쪽에서 다시 연다.
- 카카오 계정 저장은 방장 token 검증 뒤 공개 네트워크 token만 AES-256-GCM으로 암호화해 방당 한 계정에 연결한다. 방장 token은 저장하거나 계정에 이전하지 않으므로 다른 기기에서는 공개 결과만 재열람하며, 방 관리는 최초 기기 또는 방장 권한이 URL fragment에만 포함된 별도 관리 링크가 필요하다.
- 스토리 카드는 참여자 이름·개별 점수 없이 인원·관계 수·최고 등급 같은 집계만 사용한다. 동적 OG는 공개 방장 별칭과 집계만 노출한다.
- 생년정보는 전용 Production 키로 암호화하고 30일 뒤 조회 차단 및 자동 삭제한다.
- 새 유료 1:N 주문은 중단하지만 기존 구매 결과와 복구 경로는 유지한다.

## 계산 / AI

- 사주·궁합 계산은 서버 결정론 로직이 수행한다.
- AI는 계산 결과를 바꾸지 않고 서술만 생성한다.
- 유료 1:1·1:N 서술 기본 모델은 `claude-sonnet-5`.
- 이름/원본 생년월일시는 외부 AI에 직접 전달하지 않는다.
- 결제가 서버에서 검증된 뒤에만 유료 AI 생성을 실행한다.
- 동일 결제/세그먼트 AI 중복 호출을 막는 single-flight/idempotency를 유지한다.
- 저장된 기존 구매 결과는 임의 재생성하지 않고 저장 결과를 재열람한다.
- 1:1 ACTION 모델 출력은 새 화면의 핵심 필드만 필수 JSON 스키마로 요구한다. 레거시 `situationStrategy`와 `actionPlan30`은 핵심 결과에서 서버가 결정론적으로 조립해 저장 호환을 유지한다.
- `AI_FORMAT` 복구는 같은 결제로 자동 1회만 재시도한다. 재실패 시 새 결제를 만들거나 무한 호출하지 않고 같은 결제 수동 재시도 UI를 제공한다.
- AI 형식 오류 로그에는 사용자 서술 원문을 남기지 않고 실패한 JSON 경로와 기대 타입만 남긴다.

## 저장 / 계정 / 보안

- 서버 DB(Neon)가 주문·결제·완성 결과의 권위 데이터다.
- 브라우저 저장소는 재개/복구 보조 사본이다.
- 결과 접근 토큰 원문은 서버에 저장하지 않고 SHA-256 해시를 사용한다.
- Kakao 로그인은 선택형이며 비회원 결제 흐름을 유지한다.
- 계정 소유권 검증 없이 유료 결과를 열람하게 만들지 않는다.
- 회원탈퇴·결과 삭제 시 정의된 삭제 대상 데이터 정리 원칙을 유지한다.
- 비밀값은 코드·로그·문서·GitHub에 커밋하지 않는다.

## 결제 / 운영

- PortOne 서버 검증 이전 유료 결과 생성 금지.
- PortOne 결제창을 열기 전에 서버 DB 주문 행, access-token hash, 상품·금액, 입력 hash를 확인한다. 서버 주문 저장소가 없거나 확인 불가하면 결제를 시작하지 않는다.
- 서버 주문 저장 실패를 브라우저 전용 주문으로 대체해 유료 결제를 진행하지 않는다.
- 이미 paid인 동일 paymentId는 새 결제를 열지 않고 기존 결과 복구 경로로 보낸다.
- webhook 및 주문 처리는 멱등성을 유지한다.
- 1:1 / 1:N 가격·상품 ID·금액 검증을 서버 권위로 유지한다.
- Vercel Git 자동배포는 기본 비활성화한다.
- Preview 배포는 사용자가 상시 승인했다. 변경 검증이 끝나면 별도 재확인 없이 배포하되 Git 자동배포는 다시 OFF로 복구한다.
- Production 배포는 사용자 명시 승인 후 수행한다.
- Vercel Authentication은 안정적인 Production 별칭을 공개하고 Preview와 개별 Production 배포 URL을 보호하는 `prod_deployment_urls_and_all_previews` 범위를 사용한다.
