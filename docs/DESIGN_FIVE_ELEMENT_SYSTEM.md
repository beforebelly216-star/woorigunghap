# 오행 밸런스 시스템 — 디자인 스펙 v1

> 2026-08-25 사용자 확정. 기존 라벤더 파스텔 마스코트 비주얼 아이덴티티를 대체한다.
> `docs/DECISIONS.md`의 리포트 섹션에서 이 문서를 참조한다.

## 컨셉 한 줄

오행 5색을 장식이 아니라 **항상 보이는 기능 정보**로 쓴다. 5색 바와 점수 링이 모든 핵심 화면에 반복 등장하는 시그니처 요소다.

## 컬러 토큰 (제안값 — 실제 화면 적용 시 화면별로 미세조정 가능, 오행 5색과 잉크 컬러 정체성은 유지)

```
--saju-bg-base:   #FAFAF8   /* 중성 오프화이트 캔버스, 기존 라벤더 배경 대체 */
--saju-bg-card:   #FFFFFF
--saju-bg-soft:   #F1F0EC
--saju-ink:       #26262A
--saju-ink-soft:  #6B6B72
--saju-border:    #E6E4DF
--saju-track:     #ECEAE4

/* 오행 5색 — 기능색, 절대 장식으로만 쓰지 않는다 */
--saju-element-wood:  #4C8C5C   /* 목 */
--saju-element-fire:  #D65B4A   /* 화 */
--saju-element-earth: #C99A3E   /* 토 */
--saju-element-metal: #8B93A6   /* 금 */
--saju-element-water: #3E7DAD   /* 수 */

/* 단일 강조색은 별도 브랜드 컬러를 새로 만들지 않고 잉크(--saju-ink)를 그대로 쓴다 */
```

**다크모드는 지원하지 않는다 (2026-08-25 사용자 확정, 방향 전환).** 기존 `report-theme.css`의 `prefers-color-scheme: dark` 블록과 `globals.css`의 관련 블록은 삭제했다. 라이트 팔레트 단일 구성으로만 서비스한다.

`--saju-primary` / `--saju-accent` / `--saju-blush` / `--saju-mint`는 스펙의 신규 토큰이 아니라, 기존 컴포넌트들이 참조하는 레거시 토큰명을 유지하기 위한 **중립 호환 톤**이다(여러 파일에서 이 토큰들을 배경색으로 쓰고 하드코딩된 어두운 텍스트(`#3A3550`)와 짝지어 놓아서, 잉크색처럼 어둡게 바꾸면 버튼 글씨가 안 보이게 된다). 스펙이 말하는 **실제 단일 강조색은 `--saju-primary-deep`(잉크, `#26262A`)** 하나뿐이다.

## 타이포그래피

- **데이터/헤드라인**: IBM Plex Sans KR (bold 700) — 점수, 화면 제목처럼 "근거 있는 계산"이라는 인상이 필요한 곳
- **수치(tabular)**: IBM Plex Mono (600~700) — 점수 숫자, 퍼센트, 오행 수치 등 모든 숫자
- **본문**: 기존 Pretendard 유지 — 가독성 좋은 장문 리포트 본문체를 바꿀 이유 없음. `--saju-font-sans` 토큰은 유지
- **명조체(`--saju-font-serif`, Nanum Myeongjo)**: 오행 시스템에서는 기본적으로 쓰지 않음. 특정 챕터 인용구 등 예외적으로만 검토

## 레이아웃 원칙

1. **오행 5색 바**: 핵심 화면 상단에 고정 등장하는 시그니처 요소. 장식이 아니라 그 사람/그 관계의 실제 오행 비중을 보여준다 (계산값은 기존 `snapshot`/`facts`에서 그대로 가져오고 새로 계산하지 않는다).
2. **점수 표현**: 원형 게이지 대신 오행 5색으로 분할된 링(conic-gradient 5구간)으로 표현하고 중앙에 숫자.
3. **카드형 박스 남용 자제**: 얇은 보더(`1px solid var(--saju-border)`)와 여백으로 위계를 표현. 그림자/그라디언트 장식 최소화.
4. **배경은 중성 단일톤**: 오행 색이 콘텐츠 안에서 도드라지도록 배경 자체는 장식하지 않는다.
5. 결제/생성/계산 로직, 리포트 챕터 구조, 사주소년 화자/카피는 전부 유지 — 이 문서는 **순수 비주얼**만 다룬다.

## 화면 적용 순서 (2026-08-25 방향 전환 후 확정)

`theme-unification.css`가 헤더/푸터/입력폼/버튼/카드 등 대부분의 공유 UI를 이미 전역 `--saju-*` 토큰에 연결해 두고 있다는 걸 확인했다. 화면별로 CSS 모듈 스코프에 색을 따로 박아 넣는 이전 방식은, 아직 안 바뀐 헤더/푸터와 색이 어긋나 보이는 문제(2026-08-25 홈 화면 1차 시도에서 실제로 발생, 되돌림)만 만들었다. 그래서 접근을 바꾼다:

0. **헤더/푸터 + 전역 토큰(`report-theme.css`)** — 가장 먼저 진행. 전역 토큰 값 자체를 오행 팔레트로 바꾸고, `theme-unification.css`로 이미 연결된 화면들(헤더/푸터/입력폼/버튼/카드 다수)이 한 번에 일관되게 바뀌는 걸 확인한다.
1. 홈 (`home-p5.module.css`는 이미 전역 토큰만 참조하므로 0번 작업만으로 자동 반영됨, 잔여 하드코딩 값만 개별 확인)
2. 입력 / 결제
3. 생성중
4. 1:1 결과 — 2026-08-25에 추가된 hero 다음행동(`전체 리포트 읽기`/`지금 공유하기`) 구조는 유지하고 색 토큰만 오행 시스템으로 교체
5. 1:N 결과 (`comparison-*` 클래스 체계, 1:1과 별도 작업)
6. 보관함 / 계정

**남은 레거시 서식**: `globals.css`에는 Day17~19대의 별도 팔레트(Georgia 세리프, `#273b31` 다크그린 등)가 `theme-unification.css`로 덮이지 않은 세부 장식(예: `.rank-chip`, `.candidate-tip`, `.score-hero-card` 내부, `.detail-score-table`)에 하드코딩 값으로 남아 있다. 이건 4~6번 화면 작업 시 해당 화면을 만지면서 같이 정리한다 — 지금 한 번에 다 걷어내지 않는다.

## 검증

화면 하나를 바꿀 때마다 최소:

```bash
npm run lint
npm run build
```

그리고 `npm run test:report:p5-ui`, `npm run test:hotfix:runtime-ux` 등 해당 화면의 기존 계약 테스트를 함께 실행한다. 이 테스트들은 색상 hex 값을 문자열로 검사하는 경우가 있으므로(P5 unified pastel 토큰 검증 등), 토큰을 바꾸는 화면에서는 관련 assertion도 함께 갱신해야 한다.
