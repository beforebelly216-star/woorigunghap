# 우리사주 화면 개편 — 단계별 실행

## 공통 원칙
- 화이트·잉크·딥그린. 그라데이션/그림자는 강조 수단으로 반복하지 않는다.
- 정보 순서와 화면 배치를 먼저 정하고 색·장식을 적용한다.
- 모바일 360/390/430px와 데스크톱에서 폭·줄바꿈·탭 영역·고정 메뉴를 검증한다.
- 주요 본문 16px, 설명 13~14px, 섹션 제목 21~24px. 화면당 주요 행동 하나.
- 실제 점수, 등급, 계산 근거와 결제/저장/권한 로직을 보존한다.

## 단계
1. 완료: 홈 + 1:1 결과의 레이아웃과 공통 테마 기반
   - 홈: 설명 → 두 사람 궁합 → 무료 서비스 목록 → 최근 결과.
   - 결과: 이름·한 줄 해석 → 점수 → 관계 내용 → 세부 지표 → 접을 수 있는 사주 근거.
   - 480px 최대 폭, 화면 좌우 여백 20~28px, 한 열 중심, 일관된 SVG 아이콘.
2. 예정: 입력 + 로그인 + 결제 + 생성/복구 상태
   - 필드 그룹, 다음 버튼, 키보드 대응, 주문 요약과 실제 처리 상태.
3. 예정: 무료 결과 + 관계망
   - 무료 결과 TOP 3 우선, 관계망 선택과 상세 패널의 계층 정리.
4. 예정: 보관함 + 공유
   - 생성/완료/복구 상태 목록, 공유 화면과 이미지의 정보량 정리.
5. 예정: 전체 회귀 검증 + 남은 레거시 CSS 정리
   - 모바일/데스크톱, 빈 상태/오류/긴 이름, 브라우저 이동 후 스타일 적용 검증.

## 1단계 검증
2026-10-02: Edge 360/390/430/1280px 홈·합성 유료 결과 검증 PASS. 가로 넘침 없음, 사주 근거 펼치기/닫기 PASS, 긴 이름·생성 중 최근 결과 PASS, 비로그인 로그인 이동 PASS, pageerror 0.
UI·지표 근거·공유·카카오 인증 contracts 4종 + lint + TypeScript + production build(34/34) PASS.
Windows tsx userInfo ENOMEM은 테스트 프로세스 전용 shim으로 해결했고 종료 시 삭제했다.
임시 합성 결과 route는 삭제했고 production build에 포함되지 않는다.
합성 결과는 디자인 검증에만 사용하며 구매 결과 또는 AI 품질 검증으로 취급하지 않는다.
